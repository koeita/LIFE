## 🕹️ ゲームの概要と操作方法

### 1. ゲーム概要
プレイヤーは0歳の子どもとして誕生し、毎年提示される「3枚の行動カード」から1つを選びながら人生を歩みます。  
生まれ持った才能（Traits）や16タイプのMBTI性格、学生時代の部活動、就職・転職、恋愛・結婚、資産運用（株式・不動産・カジノ）など、プレイヤーの選択と時代のトレンドによって無数の人生ドラマが紡がれます。

### 2. 基本操作フロー
```
   [1. 年次行動カードを選択]
               ↓
   [2. 行動結果トーストの確認] ── (じっくり読める / 自動で消えない)
               ↓
 ┌───────────────────────┴───────────────────────┐
 │ 【イベントが発生した場合】                    │ 【イベントがない場合】
 │ 画面のどこかをタップするとトーストが消え、     │ トーストが出たままでも、次の年の行動カードを
 │ ドラマチックにイベントモーダルが開く         │ そのまま連続タップしてサクサク進められる
 └───────────────────────┬───────────────────────┘
                         ↓
         [3. 自由行動・人生アルバムの充実]
     (15歳以降：恋愛、ペット、趣味、投資、起業など)
                         ↓
               [4. 臨終・エンディング]
      (人生ステータス推移グラフ、称号、アルバム鑑賞)
```

## 💡 【技術的なこだわり・設計の工夫】

### 1. ゼロ依存（Zero Dependencies）と瞬時起動の追求
* 外部ライブラリや重厚なSPAフレームワークを一切導入せず、純粋なVanilla JSとCSSのみで構築しました。
* 音声アセットも外部音声ファイルをロードせず、**Web Audio APIを用いて周波数・エンベロープ（ADSR）をリアルタイム合成**しています。これにより、**初回ロード時間ほぼ0秒、通信量数十キロバイトでの瞬時起動**を実現しています。

### 2. 堅牢な単一状態管理（Normalized State Machine）
* プレイヤーの人生の全状態はグローバルなステートオブジェクト `S` で一元管理され、毎ターンの行動決定時に `saveCurrentGame()` で `localStorage` へアトミックに同期されます。
* 過去のセーブデータやバージョン差異による不整合を防ぐため、`ensureState()` によるフォールバック機構を導入し、安全なデータマイグレーションを保証しています。

### 3. モバイルファーストの快適なレイアウト（App-like UI）
* スマートフォンでの快適な操作性を追求し、画面全体のバウンススクロールやダブルタップ・ピンチズームを制御。
* ヘッダー（ステータス表示・メインメニューボタン）をビューポートに完全固定し、中央コンテンツ領域およびモーダル内のみを独立スクロール可能にする設計を採用しました。

## 🔥 【開発中に直面した課題と解決エピソード】

### 課題1: リロードによる「不正なやり直し（リセマラ）」と画面断絶
* **【直面した課題】**:  
  ブラウザゲーム特有の問題として、「転職活動や大勝負イベントで望まない結果が出た際にページをリロードして巻き戻す」リセマラ行為が可能になっていました。また、プレイ途中でリロードした際に毎回タイトル画面に戻されてしまい、再開の手間がかかるというUX上の課題がありました。
* **【解決アプローチ】**:  
  1. 起動時に `localStorage` のセーブ状態と最終画面を検知し、タイトルを経由せず**直接プレイ中のゲーム画面へ即座に自動復帰**するレジューム機構を構築。
  2. 行動カードを選択した瞬間に `S.turnActed = true` および保留中のイベント識別子（`pendingActionId`）をリアルタイム保存。
  3. もし転職モーダル表示中にリロードされた場合でも、**カード選択画面には戻さず、転職求人モーダルを目の前に強制自動復帰**させるターン永続化ステートマシンを実装。これにより、不正な再抽選を物理的に防止しました。

### 課題2: 非同期モーダルと結果通知トーストの「文字被り・読み逃し」
* **【直面した課題】**:  
  行動カード選択直後にステータス変化（例: 知力+3）を知らせるトーストが表示されますが、直後にランダムイベントやマイルストーンが発生すると、イベントモーダルが上から被さってしまい、トーストのテキストを読む前に隠れてしまう問題が発生しました。
* **【解決アプローチ】**:  
  1. トーストの自動消去タイマーを完全撤廃し、プレイヤーが確認するまで画面に留まる仕様に変更。
  2. **イベントがある場合**: トーストを表示した状態で待機し、プレイヤーが画面上のどこかをタップした瞬間にトーストが消えてイベントモーダルが開くフローを実装。
  3. **イベントがない場合**: トーストが出たままでも、次の年の行動カードを直接タップ可能にし、タップした瞬間に次のターンの処理へシームレスに上書き更新される設計にしました。
  4. イベント内でアルバムスナップを獲得した際も、画面下のトーストを抑制し、モーダル内のチップ（ゴールドバッジ）として同列表示することで、視覚的な重なりをゼロにしました。

### 課題3: 自由行動メニュー追加時における既存要素（職業等）との干渉防止
* **【直面した課題】**:  
  ゲームをより面白くするため「趣味・ペット」「田舎移住」「海外カジノ」などの個性派ルートを追加する際、既存の就職先（「動画配信者」など）や副業システムと仕様が重複・干渉し、ゲームのコンセプトがブレる懸念がありました。
* **【解決アプローチ】**:  
  既存コードの回帰テストをPlaywrightで網羅的に実施しつつ、通常職業リストから「動画配信者」を整理・削除し、一般職とユニークな生き方の住み分けを明確化。自由行動メニューを4ボタン体制（恋愛・趣味・資産・起業）へ綺麗に再設計することで、既存のシステムを破壊することなく新要素を完全に統合しました。
